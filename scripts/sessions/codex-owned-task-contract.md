# Owned Codex Task boundary

The Codex branch is explicit: `CodexTaskStartRequest` carries `provider: "codex"` and Task-only options. The original untagged Claude request, parser, snapshot and canonicalization remain their own branch. A fixed Claude Start hash regression protects existing UUID retries. A smith name never selects or changes a provider implicitly.

`createCodexOwnedTaskService` reserves the original UUID/content hash in the existing checked registry, then prepares under the addressed conversation lease. The private `codexTask` snapshot is separate from the existing Claude `session` field. Current project/repository/worktree/bead/About checks belong to the injected scope validator, before and after native capability preparation. Exact retries reconstruct the original private snapshot before fresh capability checks and never dispatch another Task. A Task accepts one turn.

The registry shares one original-UUID lock and bounded metadata file. Its default API retains the Claude partition; an explicit `"codex"` selection admits only the Codex metadata branch. `lookup` and `listAll` are observations for trusted provider routing, never dispatch authority. A UUID collision across providers or projects refuses before preparing a second request.

The existing Keeper wire and journal codec reject Codex-only intent and usage. Only a trusted addressed coding partition uses `ownedCodingStateSchema` and its page/event codecs. They validate the exact prompt, context project and reported provider binding. `coding-usage` is private, explicitly sourced from `exec.turn.completed`; absent counts remain absent. Requested effort `default` on a process frame means CLI configuration behavior. No observed model, cost or allowance is inferred.

The transport adapts the supervised Task runtime's actual UUID, deduplicated text and reported usage into private events. Text is split at Unicode character boundaries to respect the journal frame limit. Stop and timeout retain the runtime's actual tree cleanup and persistence deadline. The callback still enforces the journal's owned lease/revision; no provider or tool body is projected into Activity by this module.

The existing audited Preview and Start routes select this branch only for an explicit Codex request. Preview prepares capabilities without reserving a session or dispatching a provider. The dedicated Codex Task pane shares prompt, About context and confirmed worktree selection with the Claude composer while retaining separate model/effort/sandbox choices. An unknown Start keeps its original provider and body across draft edits and provider switches. Lists and Activity expose metadata only; the protected private conversation shows actual native identity and reported token counts, with the observed model explicitly unreported.

Both provider panes reserve a browser Start identity under an origin-wide Web Lock before POST. The bounded versioned journal stores only project ID, original UUID, canonical request hash and provider. It stores no prompt, attachment, path or model. Reload or another window retains the hold even if the server list is empty, and never resends automatically. A reloaded browser without private input offers only a protected check. The hold releases after matching protected registry hash/provider/UUID and evidence of the admitted original turn, or a trusted local `NotSent` outcome that proves the request never left the browser. Generic refusals, malformed/network outcomes and failed durable erasure remain held; corrupt/future/full records are preserved without eviction.

This increment does not implement Chat, native permission responses, image/schema staging or model/account discovery. Chat remains unavailable until a separate app-server producer and approval lifecycle are integrated. A configured effort without exact model/version evidence remains selected and refuses preparation until the operator explicitly changes it; selecting CLI default is an explicit choice.
