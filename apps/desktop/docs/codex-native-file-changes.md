# Private native Codex Chat file snapshots

This additive Chat-only family inspects native file-change reports. It grants no filesystem read, patch application, editor, shell, launch or approval authority. Reported paths and move destinations remain private display text; no reported path is resolved, inspected or opened. Existing file-change Allow refusal remains independent of visible diff text. Task, Claude, Gemini and sealed Keeper protocols and original request hashes are unchanged.

Primary contract evidence is the local model-free generation from Codex CLI `0.163.0-alpha.10.2`: `.tmp/work/codex-protocol-0.163/v2/ThreadItem.ts`, `FileUpdateChange.ts`, `PatchChangeKind.ts`, `PatchApplyStatus.ts` and `FileChangePatchUpdatedNotification.ts` in the main checkout. The native item carries `id`, complete `changes` and `status`; each change has `path`, `kind` (add/delete/update with nullable `move_path`) and a required `diff` string. The patch-updated notification carries the exact thread/turn/item identity and a full changes replacement, **not a delta or a new status**. The generated `FileChangeOutputDeltaNotification.ts` explicitly marks that old method deprecated and no longer emitted. It is not a producer here.

`CodexChatFileChange` and `codexChatFileChangeSchema` add one strict private `coding-chat` event variant. Every report names the source, native thread/turn/item, observed patch status, retained complete replacement snapshot, truncation, partial state, closure and nullable native turn status. Paths, move destinations and diffs use the existing `ReportedText` shape. The whole retained snapshot shares a 16 KiB text budget and 128-change limit; the existing 64 KiB event, 2 MiB shared rich-report and 256 native item limits remain in force. A truncated or normalized body stays visibly distinguished from full native text.

`item/started` establishes an in-progress item. `item/fileChange/patchUpdated` requires that exact active item, retains its last observed in-progress status with notification provenance, and replaces the complete current changes display. An empty `changes: []` is a legitimate replacement and clears prior files. Exact native duplicate reports are idempotent; distinct replacements remain distinct retained reports. Snapshots are never concatenated as diff fragments.

`item/completed` requires a non-in-progress native patch status and closes that item. One later matching `turn/completed` snapshot can add its distinct turn closure and actual terminal status; changed completed content or any later patch update is refused. A final turn may still report an in-progress file item, which remains partial. A failed/interrupted native turn remains partial even when its last patch item status was completed. Patch status never establishes successful application or turn completion by inference.

A required native diff that is absent or malformed is refused. A provider-reported **empty string** is retained exactly with `truncated: false`; the renderer calls it “Provider reported an empty diff.” Empty retained text with `truncated: true` instead means omitted/normalized content and is labelled separately. No diff is reconstructed from Git or workspace files. Whole private history and protected partial-page codecs preserve current provider/thread/version/turn binding; whole history also checks process ownership, shared item kinds, closure chronology, terminal status compatibility and shared aggregate bytes.

The collapsed read-only disclosure selects the last supplied full snapshot per exact native item. It shows native status and source separately from item and turn closure, with literal escaped diff/path/move text and a keyboard-scrollable patch region. An explicit empty replacement clears the current list. It supplies no file links or action controls; failed, declined and in-progress items are never labelled applied. A partial page can show a self-contained full snapshot only under its protected version/thread binding and one consistent native turn.
