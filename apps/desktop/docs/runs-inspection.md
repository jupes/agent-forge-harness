# Scoped run inspection

This child adds inspection of canonical Forge runs from the checkout served by the hearth. It grants no artifact-content read, session control, pipeline launch or checkpoint action. The desktop parent remains open for those separate producers.

The protected operator-table reads are `GET /__agent-forge/projects/:id/runs` and `GET /__agent-forge/projects/:id/runs/:slug`. They accept no query paths, alternate roots or commands. Both require operator authorization and return the existing operator envelope. Reads append no action event.

`types/project-runs.ts` and browser-pure `scripts/projects/run-protocol.ts` define version 1 list/detail responses. Every response names its project, ledger workspace, actual served checkout, read time and `served-checkout-only` coverage. The receiver cap is 512 KiB. Run rows use the existing pure run/phase/status/health selectors. Full/Mini and Started are not recorded by ForgeState and are not fabricated. Historical `auto` records grant no new unattended launch authority.

The source uses the existing project catalog and a live bounded Beads export. It re-reads the catalog after awaiting the export, checks explicit epic ancestry plus the project label in this served workspace, and requires any stored bead to remain a member. Any stored checkout must match the served checkout, including its configured or canonical Windows spelling. A linked worktree's shared main ledger workspace is not an alternative checkout. Missing/incomplete membership refuses the read. The membership-only snapshot option leaves existing consumers unchanged and reads no run registry, session ledger or private session registry.

`scripts/forge/inspection-read.ts` captures the served root's actual filesystem identity. It never calls listRuns or any migration/writer. Per-run JSON must be a single plain unlinked file with matching filename/slug, known schema, valid canonical fields and stable opened/named identity. Missing files during enumeration, malformed/future/oversize/linked/retargeted sources are refused and preserved. Limits are 128 run files, 1,024 directory entries, 512 KiB per run and 8 MiB aggregate source bytes. Individual directories are enumerated through a bounded stream. Strict validation precedes the existing canonical parser/selectors.

Gate inspection uses the existing fixed hook log root, or an explicitly trusted embedding/test override. No browser selects it. The newest 30 log-day directories are inspected with a 2 MiB per-file and 8 MiB aggregate cap, at most 20,000 nonempty lines and 256 KiB per line. The existing gate selectors retain one current and at most ten earlier entries per run. Wrong checkout/run and explicitly foreign project bead entries cannot establish this run's gate. Valid legacy evidence is labelled and never counts as linked success; an unlinked gate cannot be assigned to this run. Incomplete/future/malformed entries do not become results, and the response reports their omission. A missing matching result means no valid result in the inspected window, not a claim that no check ever ran.

Only bounded gate metadata is projected: names, recorded pass/skipped facts, the existing first-line detail, time, checkout/branch and correlation/evaluator-evidence kind. Raw output bodies and host identity are omitted. Reviews retain bounded phase/round/verdict/severity/summary/time metadata. Artifact paths/existence are metadata only and use canonical phase paths; no file body is returned.

Backend behavior-first evidence covers missing-route refusal, no legacy migration/write, current membership changed during a held export, actual linked-worktree/main separation and project/run/checkout gate correlation. Private file and wire regressions cover corruption, future versions, invalid UTF-8, size/file-count caps, links, root retargeting, duplicate slugs, phase order and foreign history bindings. These checks use FakeBd and disposable ordinary OS temporary files. UI, actual browser, packaged native, full-suite and hosted evidence is recorded separately when those stages are completed; no such result is implied by this backend checkpoint.
