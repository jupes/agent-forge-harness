# Scoped run inspection

This child adds inspection of canonical Forge runs and an explicit, protected read of completed phase artifacts from the checkout served by the hearth. It grants no session control, pipeline launch or checkpoint action. The desktop parent remains open for those separate producers.

The protected operator-table reads are `GET /__agent-forge/projects/:id/runs`, `GET /__agent-forge/projects/:id/runs/:slug` and `GET /__agent-forge/projects/:id/runs/:slug/artifacts/:kind`. They accept no query paths, alternate roots or commands. All require operator authorization and return the existing operator envelope. Reads append no action event.

`types/project-runs.ts` and browser-pure `scripts/projects/run-protocol.ts` define version 1 list/detail and artifact responses. Each names its project, ledger workspace, actual served checkout, read time and `served-checkout-only` coverage. Metadata keeps its 512 KiB receiver cap. Artifact responses contain the canonical relative artifact path, UTF-8 byte count, SHA-256 and complete body; the file is capped at 512 KiB and its JSON receiver at 4 MiB. Run rows use the existing pure run/phase/status/health selectors. Full/Mini and Started are not recorded by ForgeState and are not fabricated. Historical `auto` records grant no new unattended launch authority.

The source uses the existing project catalog and a live bounded Beads export. It re-reads the catalog after awaiting the export, checks explicit epic ancestry plus the project label in this served workspace, and requires any stored bead to remain a member. Any stored checkout must match the served checkout, including its configured or canonical Windows spelling. A linked worktree's shared main ledger workspace is not an alternative checkout. Missing/incomplete membership refuses the read. The membership-only snapshot option leaves existing consumers unchanged and reads no run registry, session ledger or private session registry.

`scripts/forge/inspection-read.ts` captures the served root's actual filesystem identity. It never calls listRuns or any migration/writer. Per-run JSON must be a single plain unlinked file with matching filename/slug, known schema, valid canonical fields and stable opened/named identity. Artifact bodies use the same captured root and strict named/opened file checks: linked files/directories, hardlinks, retargeting, malformed UTF-8, NUL and oversized bodies are refused whole, never truncated. Missing files during enumeration, malformed/future/oversize/linked/retargeted run sources are refused and preserved. Run limits are 128 files, 1,024 directory entries, 512 KiB per run and 8 MiB aggregate source bytes. Individual directories are enumerated through a bounded stream. Strict validation precedes the existing canonical parser/selectors.

Gate inspection uses the existing fixed hook log root, or an explicitly trusted embedding/test override. No browser selects it. The newest 30 log-day directories are inspected with a 2 MiB per-file and 8 MiB aggregate cap, at most 20,000 nonempty lines and 256 KiB per line. The existing gate selectors retain one current and at most ten earlier entries per run. Wrong checkout/run and explicitly foreign project bead entries cannot establish this run's gate. Valid legacy evidence is labelled and never counts as linked success; an unlinked gate cannot be assigned to this run. Incomplete/future/malformed entries do not become results, and the response reports their omission. A missing matching result means no valid result in the inspected window, not a claim that no check ever ran.

Only bounded gate metadata is projected: names, recorded pass/skipped facts, the existing first-line detail, time, checkout/branch and correlation/evaluator-evidence kind. Raw output bodies and host identity are omitted. Reviews retain bounded phase/round/verdict/severity/summary/time metadata. List/detail artifact path and existence remain metadata only and use canonical phase paths. A separate protected read returns the body only when a completed research, plan or ship state records that exact canonical path; `implement` has no artifact.

Backend behavior-first evidence covers missing-route refusal, no legacy migration/write, current membership changed during a held export, actual linked-worktree/main separation and project/run/checkout gate correlation. Private file and wire regressions cover corruption, future versions, invalid UTF-8, size/file-count caps, links, root retargeting, duplicate slugs, phase order and foreign history bindings. These checks use FakeBd and disposable ordinary OS temporary files. UI, actual browser, packaged native, full-suite and hosted evidence is recorded separately when those stages are completed; no such result is implied by this backend checkpoint.

The desktop Runs surface uses a dedicated read-only observer. An immutable project/workspace generation and the first protected list establish the served checkout before a selected detail can be fetched. Selection, disposal and list refresh abort and fence older details or artifact bodies; a run removed from the verified list loses its detail. Foreign or malformed replacements cannot overwrite last-good metadata or artifact text. The client checks response identity, canonical path, byte count and digest before display. Failed reads keep only clearly labelled previously verified values; they cannot establish an empty history. Existing 45-second read deadlines, separate bounded receivers and one shared window event stream remain in use. Artifact bodies live in memory only and do not enter browser persistence, event feeds or audit rows.

List search, recorded state/mode and selected run are hash-addressed for reload and Back. The detail shows canonical phases, bounded review summaries/severity counts and matching gate metadata, including Pass/Fail/Skipped/Not run. History coverage is **up to 30 retained log-date folders and 10 earlier entries**, not a complete calendar window. A completed phase's artifact is fetched only after the user presses its Read button; the shared safe Markdown view keeps raw HTML and images inert and allows only HTTP(S) links. Run-scoped Activity remains the only object navigation. New forge run is visibly disabled with the inspection-only reason. No action request dependency is present in the client.
