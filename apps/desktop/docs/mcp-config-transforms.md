# MCP client configuration proposals

`config_transform.rs` is a pure native module; no renderer command or client config access is mounted yet. It accepts only the private native context’s compiled Hearth command and fixed `--mcp-stdio --root <checkout> --home <home>` arguments. The consumer must validate that context and qualify private audit/original/receipt ownership before publication.

Claude Code and Cursor use a user-level `mcpServers.agent-forge` stdio entry. Codex uses `mcp_servers.agent-forge` with command and args. No environment values, operator grant, approval setting, URL or client executable is added. The proposal reports configured only for an exact existing entry; it never treats matching configuration as an active or trusted connection. Another entry under that name, including added environment or disabled fields, is foreign and refused.

JSON inserts at the closing brace of the existing server object (or root if missing), preserving every existing byte. A separate recursive parser refuses duplicate keys at every depth, including escaped equivalents. Invalid/nonobject/unsupported input is refused. TOML parses the complete original with the already locked parser, appends only a new named table, then requires the complete proposal to parse to the expected original values plus that entry. Sealed inline tables that cannot be extended are refused. Comments, whitespace, newline style, multiline strings, unrelated settings and other servers remain byte-identical in the original prefix or insertion surroundings. Dollar-bearing selectors are conservatively unsupported because JSON clients can interpolate them. Input and output are bounded to1MiB; invalid UTF-8 is refused. No raw error or config bytes are suitable for renderer responses or logs.

Nine Rust tests cover missing configs, exact-existing recognition, foreign and duplicate entries, unrelated private bytes/numeric spelling, JSON escaping, multiline TOML, inline tables and malformed/oversized/interpolated input. These are authored tests, not passing evidence until a hosted locked Rust test step completes. No local Cargo/helper, provider/client launch, actual client file read/write or native GUI qualification occurred.

Primary references: [Claude MCP scopes](https://code.claude.com/docs/en/mcp), [Cursor global MCP](https://prod.cursor.com/docs/mcp), [Codex MCP](https://learn.chatgpt.com/docs/extend/mcp?surface=cli), [locked TOML API](https://docs.rs/toml/1.1.8%2Bspec-1.1.0/toml/). Registry lock identities/checksums are unchanged; only the root package gains the already locked TOML edge and serde_json enables raw_value without new dependencies.
