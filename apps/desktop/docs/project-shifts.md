# Project shift boundary

Beads: agent-forge-harness-cla5.5.4.1, cla5.5.4.2 and cla5.5.4.3. Parent: cla5.5.4. Source: versioned desktop handoff 7e41bba and brief section 6.10. The settled handoff requires attended runs with every turn visible; the legacy autonomous CLI is not sufficient proof of that capability.

## Chosen interface

The selected interface is a protected project facade over the existing shift engine. Options, original-request lookup and observations are reads; Start, Stop and Recover remain separate audited operator actions. `runOptions`, `shiftOptions`, `createShiftStarts`, `runShift`, `requestStop` and `recoverShift` retain their rules.

An in-process controller could own the scheduler and provider sessions together, but would replace the launcher's process ownership and close/recovery behavior. A two-phase prepared ticket could freeze reviewed defaults before Commit, but would add ticket expiration and another authorization lifecycle. The facade needs fewer concepts while retaining explicit human Start and the existing cleanup machinery.

## Options read

`GET /projects/:id/shifts/options` is operator-only. It validates the served workspace and the current selected epic ancestry **and** `project:<slug>` label before exposing choices. Each configured bound includes its actual configuration source. Base retains the shift CLI default. An omitted per-run timeout means the remaining shift time, because the scheduler explicitly passes that remaining duration to each attempt; it does not mean the standalone executor's 30-minute default.

This read neither reserves a launch nor runs a provider. Start availability requires the installed trusted attended launcher and a non-archived project. A host without that capability refuses at the server boundary; a disabled renderer control is not authorization. The parent remains incomplete until the attended UI and packaged application journeys are verified.

## Admission and recovery contract

The private registry preserves the full reviewed bounds with a request UUID, request hash, canonical workspace, project and server-selected shift id before the single launch attempt. Its closed version-1 file is limited to 1,000 originals and 2 MiB; overflow refuses without evicting identities. Corrupt, future and linked files are retained and refused. Original/list reads remain available independently of mutable provider configuration. A lost or interrupted launch never starts again during GET or an exact retry. The additive `executionStartedAt` field is absent on older version-1 originals; reads do not migrate their bytes, and only an explicit trusted execution claim adds it.

New admission rechecks current catalog revision, archive state, selected epic ancestry and project label inside the canonical queue lock immediately before Start. It checks both current scoped export membership and the freshly shown bead's label; id prefixes grant no membership. Stop and Recover use the immutable original project/workspace binding, so an archived project cannot strand an already-owned run. Running Stop and Recover require a matching actual shift record. Stop requests cancellation; the observed terminal record after supervised child exit confirms that a recorded shift stopped. Recovery retains the canonical ownership checks, live-pid refusal and partial-progress behavior. The project facade emits only the correlated bounded metadata, never the legacy recovery response's full record or raw error prose.

### Stop during startup

The same protected, audited project Stop route also accepts a Starting original before the canonical engine has written a record. It saves an additive version-1 `startupStop: {requestedAt, completedAt}` receipt before asking the exact locally held tree to cancel. This control retains the original project, workspace, request UUID, reviewed request/hash, shift association and creation/admission times. The request hash bytes stay unchanged; mutable lifecycle receipts are not new Start authorization. Older originals remain readable without rewriting their bytes, and registry row/byte bounds still refuse overflow without eviction.

The selected interface reuses the launcher's actual owned handle. A separate durable lifecycle coordinator would duplicate its ownership model; creating an early canonical record would invent start/deadline/cost observations before the scheduler established them. Neither is needed for this control. The ordinary global Shift route retains its existing refusal before a record exists, and generic conversation Stop markers grant no engine authority.

Only settlement of that matching held tree, followed by absence of any canonical record, allows `completedAt` and a Stopped receipt with `actual: null`. No PID probe can confirm it. If the host restarts without the matching handle or a Stop/completion write is unverified, the result stays unknown and the original remains held. Exact Stop requests coalesce on the held handle. A canonical record that appears during cancellation wins, including Needs recovery after its owner exits; the facade does not fabricate metrics or release its owned work. Reads never dispatch or complete an unknown control.

A saved startup Stop refuses a late launcher invocation, ownership grant, execution claim and subsequent engine admission. A late Start reply re-reads that durable truth. The renderer offers Stop while Starting, keeps native keyboard focus, retains a lost control result across reload, and releases the browser identity only after a strictly verified settlement. No saved original is automatically resent.

The packaged launcher has an explicit `--project-shift-run <projectId> <originalUUID>` entry. It reads the private original, requires its launch-attempt marker and claims engine entry once before mutable preparation. Reservation, launch-attempt and execution markers are distinct; none proves a provider turn. Trusted child commands append only those two ids and use the base environment allowlist. The project path holds an owned bootstrap before engine code runs, rechecks the exact original and canonical cwd immediately before its grant, confirms the separate engine identity and sends EOF without a payload. The wrapper is never substituted for the engine PID in its actual shift record. Normal exit drains output only after terminating the held job/group; abrupt host death also ends nested attended provider trees. Ordinary global shifts retain their existing launcher. Source execution uses the same closed protocol.

Attended execution captures actual provider turns from the executor path into owner-only journals. Raw output, prompts and provider error prose never enter ledger metadata. Until attended turns and controls are visible and verified in the browser and native app, the parent feature remains incomplete.

The trusted `ShiftDeps.captureAttempt` factory receives the actual shift, bead, run and attempt number. Its owned bootstrap persists the actual provider process before one-shot input and retains the private lease through held-tree cleanup. A private storage/protocol failure latches a fixed reason, stops all active runs and refuses repairs and new claims, including a claim whose scope check was already waiting inside queue ownership. Existing owned cleanup then releases the queue and reservations before the shift reports halted. No private capture factory is selected by ordinary CLI flags or a model tool; ordinary shifts keep their existing execution path.

Private lifetime grants name either a shift attempt or the outer shift engine. An attempt receives the exact prepared per-run timeout or remaining work time, bounded by the canonical 24-hour shift limit; it is never silently shortened to the interactive provider's default 30 minutes. The outer engine adds five minutes of bounded preflight/finalization grace. The parent timer and bootstrap grant share the same validated value. Ordinary interactive providers retain the 30-minute limit, and ordinary buffered execution is unchanged.

Attended records add a latest host sample with its time, measured CPU and memory shares, and admission-throttled flag. Missing or invalid shares remain unknown. Optional host metadata never grants or removes Stop/Recover authority. The configured threshold, sample time and actual shift phase remain distinct observations.

## Private attempt observations

`GET /projects/:id/shifts/requests/:requestId/attempts` exposes the bounded private index for that immutable original. Index entries explicitly remain unknown: metadata alone proves neither a provider turn nor its completion. The selected `/:sessionId` body page verifies the original reviewed bounds, deterministic attempt request id, full actual input hash, first private user, provider binding, process selection and completed outcome before returning any page. A missing or corrupt journal refuses the body read while preserving the metadata and saved bytes. An abandoned active journal projects unknown without rewriting it.

The operator-only `/:sessionId/events` feed reuses the existing private conversation feed, including its cross-process observation and cursor bounds. Every body read rechecks the immutable correlation. These observers have no process control authority. Generic coding session reads, sends and Stop refuse managed shift origins; whole-shift Stop and Recover remain the canonical controls. The all-provider registry metadata accessors retain explicit `origin: {kind: "shift", projectId, originalRequestId, shiftId, runId, beadId, attempt}` for ownership and deduplication. Absence from the generic controllable session list does not mean that a managed attempt is external.

The attended child-runtime composition reuses the canonical scheduler, current project admission, worktree registry, bounds and cleanup. It supplies mandatory private capture and a Codex adapter with explicit `approval_policy="never"`; ordinary adapter arguments stay unchanged. Before private input, the runtime checks fresh project membership and the matching persisted active attempt, including its run, repair number, smith and actual working directory. CLI version/help probes and Codex skill sync are bounded and cancellable. Retained PR bodies use the same canonical validator through a bounded file reader, so the packaged child never invokes source-only `bun run pr:check`. Compiled-fake tests cover both providers, exact argv/stdin, no duplicate execution, scope loss, whole-shift Stop and fatal private-protocol cleanup. The closed source/packaged entry installs this composition and consumes only its already authorized original once; unavailable current scope preserves an unknown receipt. The protected server Start route uses this mandatory owned project path; it does not enable or change the global autonomous Start surface.

## Verification

The first tracer verifies exact configured defaults and provenance, scoped epic choices, a protected real-hearth options read and absence of launches, durable reservations and tracker writes. Subsequent admission tests cover audit ordering, immutable original requests, crash boundaries, fresh per-admission scope and workspace fences. ## Workbench attendance

The project Workbench now places bounded shifts above its existing board. Its shared Nocturne buttons and native dialog expose the actual configured duration, concurrency, maximum beads, spend cap, repair count and their sources, plus base, current epic filter, optional smith override and optional per-run timeout. The source brief's exact Workbench-to-shift board was unavailable in the cached gallery; this implementation reuses the actual shared Workbench/Dialog design system and does not claim to reproduce that absent board.

Opening, editing and Cancel only read defaults. Explicit Start first durably saves a bounded UUID/hash-only browser identity under an origin lock. The private original body remains on the server. Unknown POST results and protected404 retain the original identity and hold replacements across navigation, reload and other windows; reads never resend it. A verified stopped original can release its browser hold. Fresh options or catalog revision changes require explicit review again.

The panel shows the actual start time and elapsed/limit, correlated actual limits, admitted/active/reviewed/halted counts, reported spend and unpriced attempts, and the last actual host admission sample. Starting, Running, Throttled, Stopping, Stopped and Needs explicit recovery remain distinct; Failed to start, Outcome unknown and an original saved without an observed launch have explicit wording. Each canonical stopped reason is shown separately. The panel does not invent PR, gate or halt-repair information from labels. Background reads preserve native action focus. Stop requests cancellation; only the observed terminal shift after supervised cleanup confirms Stop. Explicit Recover uses the original after interruption and remains available after archive or current provider configuration failure.

The private attempt selector follows the latest attempt or pins a selected one. Its dedicated cursor feed reads all bounded retained pages, verifies the first shift user against its registry origin, preserves exact frame sequence and provider binding, and requires actual process/identity/success-outcome proof before showing complete history as completed. Rejected indices invalidate old feed callbacks. Text, reasoning, tools, commands, file reports, plans, structured output, per-turn usage and outcomes reuse the existing inert session presentation. Closing or navigating clears the private body observer. Per-attempt Send/Stop and generic session control remain unavailable; controls act on the whole original shift.

`verify:desktop-shifts` exercises a planted temporary checkout through the real engine and compiled inert providers: Cancel/no effects, lost Start reply plus exact original/private recovery without replay, and keyboard Stop during a held read with actual provider/helper exit. `desktop:smoke` adds actual packaged Codex activity and explicit never-approval, followed by an interrupted Claude owner tree, a new native host and explicit original Recover without another provider turn. The ordinary unit, desktop, native and CI gates remain required before this child is published as verified.
