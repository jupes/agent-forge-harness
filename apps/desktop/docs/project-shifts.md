# Project shift boundary

Bead: agent-forge-harness-cla5.5.4.1. Parent: cla5.5.4. Source: versioned desktop handoff 7e41bba and brief section 6.10. The settled handoff requires attended runs with every turn visible; the legacy autonomous CLI is not sufficient proof of that capability.

## Chosen interface

The selected interface is a protected project facade over the existing shift engine. Options, original-request lookup and observations are reads; Start, Stop and Recover remain separate audited operator actions. `runOptions`, `shiftOptions`, `createShiftStarts`, `runShift`, `requestStop` and `recoverShift` retain their rules.

An in-process controller could own the scheduler and provider sessions together, but would replace the launcher's process ownership and close/recovery behavior. A two-phase prepared ticket could freeze reviewed defaults before Commit, but would add ticket expiration and another authorization lifecycle. The facade needs fewer concepts while retaining explicit human Start and the existing cleanup machinery.

## Options read

`GET /projects/:id/shifts/options` is operator-only. It validates the served workspace and the current selected epic ancestry **and** `project:<slug>` label before exposing choices. Each configured bound includes its actual configuration source. Base retains the shift CLI default. An omitted per-run timeout means the remaining shift time, because the scheduler explicitly passes that remaining duration to each attempt; it does not mean the standalone executor's 30-minute default.

This read neither reserves a launch nor runs a provider. Start availability remains false until the attended private transcript adapter is implemented and verified. The refusal exists at the server boundary; a disabled renderer control is not authorization.

## Admission and recovery contract

The private registry preserves the full reviewed bounds with a request UUID, request hash, canonical workspace, project and server-selected shift id before the single launch attempt. Its closed version-1 file is limited to 1,000 originals and 2 MiB; overflow refuses without evicting identities. Corrupt, future and linked files are retained and refused. Original/list reads remain available independently of mutable provider configuration. A lost or interrupted launch never starts again during GET or an exact retry. The additive `executionStartedAt` field is absent on older version-1 originals; reads do not migrate their bytes, and only an explicit trusted execution claim adds it.

New admission rechecks current catalog revision, archive state, selected epic ancestry and project label inside the canonical queue lock immediately before Start. It checks both current scoped export membership and the freshly shown bead's label; id prefixes grant no membership. Stop and Recover use the immutable original project/workspace binding and require a matching actual shift record, so an archived project cannot strand an already-owned run. Stop requests cancellation; only the observed terminal record after supervised child exit confirms that the shift stopped. Recovery retains the canonical ownership checks, live-pid refusal and partial-progress behavior. The project facade emits only the correlated bounded metadata, never the legacy recovery response's full record or raw error prose.

The packaged launcher has an explicit `--project-shift-run <projectId> <originalUUID>` entry. It reads the private original, requires its launch-attempt marker and claims engine entry once before mutable preparation. Reservation, launch-attempt and execution markers are distinct; none proves a provider turn. Trusted child commands append only those two ids, retain the existing supervisor/close ownership and use the base environment allowlist. Source execution uses the same closed protocol. Native smoke verifies the packaged refusal against a disposable private original without a CLI, tracker or remote.

Attended execution still needs bounded private capture of the actual provider turns from the executor path and links to their owner-only journals (child `cla5.5.4.2`). No production attended runtime is installed by this increment, so both the API's Start availability and actual Start effect remain unavailable. Raw output, prompts and provider error prose never enter ledger metadata. Until attended turns and controls are verified in the browser and native app, the parent feature remains incomplete.

The private capture checkpoints add a trusted `ShiftDeps.captureAttempt` factory with the actual shift, bead, run and attempt number. Its owned bootstrap persists the actual provider process before one-shot input and retains the private lease through held-tree cleanup. A private storage/protocol failure latches a fixed reason, stops all active runs and refuses repairs and new claims, including a claim whose scope check was already waiting inside queue ownership. Existing owned cleanup then releases the queue and reservations before the shift reports halted. No private capture factory is selected by ordinary CLI flags or a model tool; ordinary shifts keep their existing execution path. These checkpoints alone do not enable the project Start route.

## Private attempt observations

`GET /projects/:id/shifts/requests/:requestId/attempts` exposes the bounded private index for that immutable original. Index entries explicitly remain unknown: metadata alone proves neither a provider turn nor its completion. The selected `/:sessionId` body page verifies the original reviewed bounds, deterministic attempt request id, full actual input hash, first private user, provider binding, process selection and completed outcome before returning any page. A missing or corrupt journal refuses the body read while preserving the metadata and saved bytes. An abandoned active journal projects unknown without rewriting it.

The operator-only `/:sessionId/events` feed reuses the existing private conversation feed, including its cross-process observation and cursor bounds. Every body read rechecks the immutable correlation. These observers have no process control authority. Generic coding session reads, sends and Stop refuse managed shift origins; whole-shift Stop and Recover remain the canonical controls. The all-provider registry metadata accessors retain explicit `origin: {kind: "shift", projectId, originalRequestId, shiftId, runId, beadId, attempt}` for ownership and deduplication. Absence from the generic controllable session list does not mean that a managed attempt is external.

The attended child-runtime composition reuses the canonical scheduler, current project admission, worktree registry, bounds and cleanup. It supplies mandatory private capture and a Codex adapter with explicit `approval_policy="never"`; ordinary adapter arguments stay unchanged. Before private input, the runtime checks fresh project membership and the matching persisted active attempt, including its run, repair number, smith and actual working directory. CLI version/help probes and Codex skill sync are bounded and cancellable. Retained PR bodies use the same canonical validator through a bounded file reader, so the packaged child never invokes source-only `bun run pr:check`. Compiled-fake tests cover both providers, exact argv/stdin, no duplicate execution, scope loss, whole-shift Stop and fatal private-protocol cleanup. The closed source/packaged entry installs this composition and consumes only its already authorized original once; unavailable current scope preserves an unknown receipt. The server's new Start route remains unavailable pending attended UI/native proof.

## Verification

The first tracer verifies exact configured defaults and provenance, scoped epic choices, a protected real-hearth options read and absence of launches, durable reservations and tracker writes. Subsequent admission tests cover audit ordering, immutable original requests, crash boundaries, fresh per-admission scope and workspace fences. Packaged fake-provider and browser evidence must prove visible private turns, cancellation and recovery before the parent is complete. No fixture uses a real provider, tracker or remote repository.
