# Private native registration journal storage

The unmounted `private_files.rs` producer creates journal directories/files with the current token user as owner and a protected user/SYSTEM-only DACL at first visibility. It reads the owner and ACL back through the same no-follow handle before writing original bytes. Existing directories and records are validated; their ACLs are never taken over or repaired. Every record is create-only and durably synced, bounded to6MiB. File reads verify owner, allowed trustees, effective full user access, protection, no reparse point and one hard link. Ancestor and directory handles deny rename through the operation. Failures return only a fixed unavailable marker.

The only inherited-file exception is an atomic publication receipt under the caller-held protected private journal directory. Its same-handle owner and every effective allow ACE must still be user/SYSTEM only. This does not infer success from a missing receipt. Cleanup first reads and validates the exact bounded pending bytes, then marks that same handle for deletion; it never closes and deletes a path. Partial private records are retained on failure and cannot authorize a config write.

Four scratch-only Windows tests are authored for first visibility/readback/create-only durability, refusal of an existing public directory without takeover, hard-link and foreign-cleanup refusal, and exact-handle pending cleanup. They have not run yet. Native integration, protected operator authorization, durable original/attempt state, fixed-target composition and UI remain open. No actual home, credential, provider or client config was read or changed.
