# Owned Gemini ACP Chat

This backend uses the delivered native ACP runtime, not the one-turn stream-json Task runtime. The primary version/source evidence remains in [the native contract](gemini-acp-contract.md): Gemini CLI 0.65.0 and ACP SDK 0.16.1, protocol version 1.

An explicit `provider: gemini`, `route: gemini-cli`, `mode: chat` Start reserves the original UUID and hash through the existing owned registry. The existing private conversation lease prepares `user.geminiChat` before accepting and dispatching the turn. Unspecified native model, approval and sandbox options stay omitted. All prior Claude, Codex and Gemini Task hash fields are conditional and unchanged.

`coding-gemini-chat` preserves native facts, role and correlation scope. Gemini load replays history without an end marker; notifications can precede the load reply and interleave with the next prompt. Every resumed text/tool update therefore remains `scope: native-session, requestId: null`. Its enclosing journal turn is the capture address, not a provider-reported turn identity. These updates are never projected into generic answer text. Only a matching prompt result/usage and currently live permission callback are attributable to the accepted original. Context occupancy is separate from token usage. No observed execution model or daily allowance is inferred.

The private permission event is saved before the broker saves an opaque app offer identity. Public offers contain bounded actual native details and only supplied `allow_once`/`reject_once` choices; `optionId: null` cancels. Raw RPC IDs, PIDs and native session selectors never become public decision arguments. A decision UUID/hash receipt confirms saved intent only. It is persisted before releasing at most one runtime callback; exact retries reconcile that receipt and cannot replay a native answer. The runtime's existing callback signal revokes actionability on Stop, native resolution and deadlines. Persistence is bounded and late completion cannot revive an expired callback. Reads revalidate current scope and re-read live truth after awaits.

Strict private whole-state and partial-page codecs retain the separate Gemini branch. Complete transcript export includes every original snapshot and native frame; archive retains that history. Keeper's standing codec and transport are unchanged. Before the separate Gemini Chat UI is delivered, shared consumers show an explicit read-only fallback instead of Task labels, Task commands, generic follow-up or permission controls.

Verification in this backend slice uses hermetic planted projects/configuration, a compiled inert ACP provider and private disposable homes. No actual provider, account, credential or tracker call is part of these fixtures. Composer, native-history presentation and decision UI are a separate delivery.

The first Start tracer refused through the Task-only dispatch branch before the dedicated admission was added. Two-turn replay, complete export/archive, opaque once decisions and the neutral unsupported-controls regression now pass. Closed HTTP fixtures additionally cover audit before native probes, foreign repository/bead/archive scope, lost Start/decision responses, receipt reconciliation after archive, and a native terminal outcome that withdraws offers while generic turn completion is deliberately held. Stop waits for actual provider/helper exit and rechecks a held permission read after scope validation.

Fault regressions prove that offers waiting for publication count toward the same 128-offer bound, uncertain/aborted storage cannot release a late callback, altered immutable follow-up selections refuse, and corrupt decision hashes are preserved and refused by trusted storage. Hash checking stays server-side; the private wire codec is browser-pure. An actual Vite build caught and verified the removal of an accidental Node crypto import. Existing native runtime tests retain their operation, cancellation, persistence and path-retargeting bounds. The affected 15-file matrix passed 89 tests and 992 assertions; broad desktop/native/full-suite and hosted checks are separately scheduled.
