# MCP registration in the desktop app

Settings provides explicit Review, Cancel, Register and original-receipt recovery for Claude Code, Codex and Cursor. Browser windows show unavailable controls. No native config read occurs merely by mounting Settings, receiving a stream event or reconnecting. Browser state/storage contain only client enum, opaque request UUID, scope hash, expiry and fixed status codes. Same-origin reload can restore that metadata; after a new native origin, an explicit Review discovers an unresolved private native record. Registration confirmation describes configuration, never client activation, trust or successful tool calls.

The single narrow native broker accepts only review(client enum), commit(opaque UUID) and recover(opaque UUID). It checks the current owned host generation and exact main-window origin/path, and has one origin-bound main-window permission. Parent-native ready IPC supplies the actual checkout/home/compiled Hearth path and fixed agent-only --mcp-stdio arguments. Windows extended disk prefixes are compared without changing any other private selector. No renderer path, command, environment, URL or credential can select a native target.

Windows known-folder profile discovery is independent of ambient HOME/USERPROFILE. Ambiguous overrides refuse. The fixed targets are Claude user .claude.json (or CLAUDE_CONFIG_DIR/.claude.json), Codex .codex/config.toml (or CODEX_HOME/config.toml), and Cursor .cursor/mcp.json. Unsupported paths/filesystems and foreign entries are left unchanged. Pure byte-preserving JSON/TOML proposals keep unrelated settings intact. Existing exact entries are reported configured; a differing agent-forge entry is foreign. Root directory identity and reviewed file/parent identity are fenced across confirmation. Missing final client folders are created privately only after authorization; a late existing config is refused.

Confirm first invokes the common protected, duplicate-key-rejecting audited operator action. Native code requires its exact fresh private scope-bound ticket. Before publication it durably creates the owner-private exact original and pending record. User/SYSTEM-only security is supplied at first receipt visibility, including on elevated Windows tokens. A per-client share-none private lease excludes another native process through preparation, commit and recovery inspection. TxF excludes independent client writers/renames, publishes config and receipt atomically, preserves existing file identity/security, and has no ordinary overwrite/rename fallback.

Commit is requested once, only after its durable attempt fence and final generation/expiry checks. Lost/malformed/failed acknowledgments remain unknown. Exact durable receipt recovery can confirm the original request; a missing receipt never grants resend. A durable prepared original without an attempt fence, under the exclusive client lease and with no in-flight operation, proves that exact request was not sent. Private no-effect markers cover refused preparations. Recovery changes no client config and never authorizes or commits a request. Native review authority is revoked if recovery resolves an in-memory unattempted review.

Inputs are bounded to1MiB; private original JSON6MiB; receipts8KiB; local fixed NTFS paths240UTF16units; review/ticket120seconds; transaction5seconds. Synchronous filesystem calls do not have an independent cancellation guarantee. Config and receipt must share a volume. TxF is deprecated and unsupported platforms refuse. Private originals/history remain retained; no history reset, credential export, operator MCP grant, client launch or approval-policy change is provided.
