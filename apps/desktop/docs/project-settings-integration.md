# Project Settings integration and manual acceptance

The remaining implementation is now connected: project notification preferences
feed all four event consumers, persisted app master/quiet-hours policy gates
interruption, the native tray can explicitly keep the same window alive, and
Scope previews/saves every registered workspace through explicit read grants.
General, Keeper, defaults, budgets, archive/delete, knowledge and guarded cleanup
retain their existing operator contracts. Notification actions only open the
freshly revalidated original item; they never approve, allow or start work.

## Later manual bug bash

Use isolated fixture projects for the later manual session. This guide does not
reset or authorize historical native probe attempts.

1. Check all Settings sections for a created and a pre-existing project. Change
   General and Scope, reload, and confirm current values plus immutable creation
   replay. Change a different section in another window, then verify stale Save
   refuses until current data is reviewed.
2. Use the new **Authorize source…** flow for a second already-running workspace
   Hearth in the same private home. Verify cancellation/wrong folder/unavailable
   source, per-workspace choices and count/hash/time, complete aggregation, Save,
   revocation and restart requiring fresh consent. Missing sources show Unknown.
3. Check unknown authorization/Save results across reload and receiving-Hearth
   restart. Exact-result recovery must not reopen the chooser or repeat Save.
   A matching current Scope after restart must still describe old delivery as
   unknown. Archived projects retain read-only original recovery.
4. Explicitly enable window interruptions and saved project event preferences.
   Exercise halted shift, failed gate, finished council verdict and still-backed
   proposed bead. Verify app master off/quiet hours/Pause suppression and Open
   revalidation. Opt into tray keep-alive, close/open the same window, cancel
   Quit, then confirm Quit. Background failure must not pull focus.
5. Check keyboard traversal, labels, status/alert announcements, long workspace
   paths, narrow layout and disabled/error/unknown states across the sections.

Use the actual source/notification paths for native acceptance. Fake fixtures
remain evidence only for their stated headless boundaries.

## Safe rollback

Disable the Scope editor and Save routes while retaining the history parser's
compatibility with edited epic selections. Fully reverting that parser restores
its original-epic equality rule and can reject already-edited created projects;
review a catalog migration before attempting such a full rollback. Creation
originals remain unchanged throughout.
