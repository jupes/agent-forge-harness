# MCP registration authorization

The protected operator action `POST /app-settings/integrations/authorize` accepts only a client enum and request UUID. It uses the common same-origin/token/body/strict-validation/audit-before-effect runner. Missing or invalid confirmed audit context refuses before private ticket publication. The reply contains only schema version, client, request ID and authorized=true. Authorization does not read or modify client configuration and grants no operator MCP tools.

A fixed per-client private record under the actual Hearth home binds the request to that home, checkout, audit row and creation time. Only three filenames exist; no renderer selector influences their location. The existing qualified owner-only writer publishes atomically and the service requires exact private readback. Existing private directories are validated before writing. An explicit later authorized request can refresh that client’s ticket; it cannot extend an expired native review or substitute a different review/checkout. The native consumer must validate the exact fresh ticket before it writes its durable original and attempts conditional publication. Ticket contents and native config originals never enter renderer responses. Failures are redacted.

Focused fake-publication tests observed5fail before implementation and5pass/31assertions afterward. The common API fixture includes the new action in its complete origin/token/validation/audit refusal matrix; its current-head hosted result is pending. Full native consumer, Settings mounting and real client acceptance remain open.
