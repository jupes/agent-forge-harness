# Codex Chat and native approvals

The Codex composer keeps Task and Chat options separately. Chat uses the native
app-server protocol; Task keeps its existing exec request and hash. Shared prompt,
bead, About context and confirmed worktree selection survive mode changes.

The audited Preview action checks the native CLI version and help, revalidates
project scope, and returns an exact private initialization plan. It starts no
model, sync or accepted conversation. The equivalent command starts only the
stdio server; it does not include the private handshake or prompt. The selection
must still match the review immediately before Start, including an edit made in
the same browser turn as Start. The server independently prepares and validates it.

Model, effort, sandbox and approval fields wait for the asynchronous smith defaults
before accepting edits. An early selection cannot be replaced by a later default.

Chat turns keep the app's original request identity and private journal. Later
turns resume only the saved native thread. Native response and thread token
counters are displayed separately. Requested model and native thread configuration
are not evidence of the model that executed a response. Images and output schemas
remain unavailable; bounded text context travels privately on stdin.

## Decision ownership

Only the current protected live approval endpoint supplies actionable choices.
History and original-receipt reads cannot answer a callback. Command cards show
the actual command, working directory and native reason when reported. Only the
offered once, decline or cancel choice can be sent. File Allow is disabled while
actual correlated file-change details are unavailable.

Before POST, an origin lock reserves bounded browser metadata containing project,
local session, accepted turn, opaque approval, original decision UUID and choice.
No prompt, command, working directory, reason, native RPC or PID is stored there.
A reload or lost answer retains this identity without resending or minting a
replacement. Only its exact protected recorded-intent receipt releases an
uncertain hold. Recorded intent does not prove native delivery or execution.
Corrupt, future, full or unverifiable storage is preserved and blocks a new choice.

The client rechecks the live offer after waiting for its identity lock. It may
release its own reservation if it proves no POST was dispatched and the offer
has since changed. Stop, a turn/scope change, native settlement, failed validation
or a native deadline removes live controls. Same-scope background reads retain
the focused card; an older read cannot revive a consumed offer. The server remains
the authority for the callback and its exact scope throughout these races.
Approval and usage cards scroll with the private conversation, leaving the header
and reply controls available at the supported 1100-pixel window width.

Complete transcript export verifies the conditional Chat snapshot in every turn
hash. Archive and restore change only library metadata. Observed or shift-origin
sessions retain their metadata view and never gain generic Chat controls from
their spelling, recorded process ID or absence from a current process list.

## Verification

Focused tests cover strict previews, independent drafts, exact original hashes,
bounded decision storage, concurrent/recreated owners, lost answers, late reads,
withdrawn offers and failed durable erasure. Desktop journeys use a compiled inert
native app-server and actual private admission, including reload/resume, all narrow
decisions, file refusal, Stop/helper cleanup and keyboard focus. They make no real
provider, account, model or tracker calls.
